# 보고서 테스트 케이스 대응표

사용자가 제공한 테스트 케이스 및 자동화 도구 조사 보고서의 T-01부터 T-26까지를 개발 시작점과 연결했다. 아래 자동화가 존재한다는 사실과 전체 요구사항 검증이 완료됐다는 사실은 구분한다. 실제 실행 기록은 `VALIDATION.md`에 별도로 적는다.

| ID | 보고서 대상 | 현재 연결된 기반 또는 후속 작업 |
| --- | --- | --- |
| T-01 | 익명 인증 | `firebase_flow_test.dart`에서 Android SDK와 Auth Emulator 연결 |
| T-02 | 게시판 선택 | `widget_test.dart`, `demo_flow_test.dart` |
| T-03 | 게시판 미선택 | 저장소의 존재하지 않는 게시판 거절 단위 검사. 현재 UI는 게시판 선택 후 글쓰기로 진입 |
| T-04 | 피드 최신순 | 데모 저장소 정렬 단위 검사, Firebase 조회 계약. 기기 간 시각·동시 요청은 후속 |
| T-05 | 상대 시간 | 분·시·일 및 기기 시각 오차 단위 검사 |
| T-06 | 상세 이동 | 화면 테스트와 Android 데모 통합 테스트 |
| T-07 | 게시글 작성 | 체험 모드 화면 흐름과 Firebase SDK 통합 검사 |
| T-08 | 공백 본문 | 화면 입력 검증 및 Firestore 규칙 검사 |
| T-09 | 글자 수 경계 | 500개 한글·이모지 코드 포인트 단위/규칙 검사 |
| T-10 | 글자 수 초과 | 501개 입력 거절 검사 |
| T-11 | 저장 실패 | 가짜 저장 오류 시 원문 유지 화면 검사. 실제 통신 차단·지연·중복 재시도는 후속 |
| T-12 | 두 기기 동기화 | 미실행. 서로 다른 두 기기와 실제 Firebase 테스트 프로젝트에서 최종 검증 |
| T-13 | 댓글 정상 등록 | 체험 모드 화면 검사와 Firebase Emulator SDK 검사 |
| T-14 | 빈 댓글 | 입력 검증 계약과 Firestore 규칙 검사. 상세 화면 오류 UX 추가 검증 필요 |
| T-15 | 공감 토글 | 데모 저장소/화면, Firebase SDK 토글 검사 |
| T-16 | 중복 공감 | 동일 UID 문서 중복 생성·타인 삭제 차단 규칙 검사. 동시 탭 스트레스는 후속 |
| T-17 | 신고 정상 처리 | 신고 스키마·접근 제한 규칙 및 Firebase SDK 쓰기 검사 |
| T-18 | 신고 사유 미선택 | 선택 없이는 제출하지 않는 UI 구조. 취소/뒤로가기 자동화는 후속 |
| T-19 | AI 오타 교정 | 모델 미연결. 실제 모델 결과 검증 필요 |
| T-20 | 반복 표현 | 모델 미연결. 반복 후보 제시 및 원문 보존 검증 필요 |
| T-21 | 개별 적용 | 교정 범위 계약 단위 검사만 준비. 실제 AI 제안과 화면 연동 검증 필요 |
| T-22 | 되돌리기 | 화면 연결부 준비. 실제 모델 결과와 사용자 편집 충돌 검증 필요 |
| T-23 | 오프라인 교정 | 미실행. 지원 실기기·모델 준비 후 Patrol 등으로 확인 |
| T-24 | 모델 로드 실패 | 미연결 안내·원문 유지 기본 처리. 실제 모델 오류 주입 검증 필요 |
| T-25 | 긴 입력 분할/병합 | 미구현. 실제 토크나이저·구절 분할·실패 구간 원문 보존 구현 필요 |
| T-26 | AI 성능 측정 | 미실행. 동일 조건의 실기기에서 응답 시간·PSS·열 상태·배터리 관측 기록 |

Integration Test는 기본 도구, Patrol은 네트워크·비행기 모드 등 OS 제어를 위한 후속 보조 도구로 둔다. Maestro·Appium 등은 현재 설치하거나 의존성으로 추가하지 않았다. 실제 필요와 기기 환경을 확인한 뒤 선택한다.
